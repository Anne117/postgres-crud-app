# Задание №7 — веб-интерфейс к БД

Веб-приложение над той же базой «склад интернет-магазина» (ПЗ №3).
Реализовано на Flask, доступ к PostgreSQL — через `psycopg` с параметризацией
всех значений.

## Что реализовано

| Пункт задания | Где |
|---|---|
| Страница входа по логину/паролю пользователя БД | `GET/POST /login` |
| Переход на главную только после успешного входа | сессия + `login_required` |
| Главная страница с переходами к функциям | `GET /` |
| Просмотр таблиц БД | `GET /tables`, `GET /tables/<table>` |
| Добавление строк | `GET/POST /add/<table>` |
| Обновление существующих записей | `GET /edit/<table>/<id>` → `POST` |
| Журналирование неудачных попыток входа | `logs/auth.log` |
| Dockerfile с зависимостями и конфигом | `Dockerfile.web` |
| Автозапуск при старте контейнера | `CMD gunicorn …` |
| Тегированный образ | `crud-web:0.7.0` |
| Compose с образом PostgreSQL | `docker-compose.web.yml` |
| Безопасная передача параметров | см. ниже |

## Запуск

```bash
docker compose -f docker-compose.web.yml up -d --build
# → http://localhost:8081
```

Вход:

| Роль | Логин | Пароль |
|---|---|---|
| пользователь приложения | `app_user` | `user_secret` |
| администратор БД | `app_admin` | `adminsecret` |

`app_user` имеет только `SELECT/INSERT/UPDATE` — DELETE отозван, поэтому
удаление строк из интерфейса отсутствует.

## Безопасная передача параметров

1. **Значения** — всегда параметрами драйвера (`%s` / `sql.Placeholder`),
   никогда не склеиваются в текст запроса. Инъекции вида
   `1; DROP TABLE product` и `' OR 1=1 --` попадают в БД как данные.
2. **Идентификаторы** (имена таблиц и колонок) — только из белого списка
   метаданных (`information_schema`), затем `psycopg.sql.Identifier`.
3. **Группа однотипных значений** — фильтр по списку id передаётся одним
   параметром-массивом:

   ```sql
   SELECT … FROM product WHERE id = ANY(%s)
   ```

   Это исключает склейку `IN (1,2,3)` из пользовательского ввода.
4. **Пароль БД** не попадает в cookie: в браузере хранится только случайный
   идентификатор сессии, сами учётные данные лежат на сервере.
5. **Неудачные входы** пишутся в `logs/auth.log` с IP, логином и причиной.

## Демонстрация (пп. 1.1–1.5)

1. Открыть `http://localhost:8081` → страница входа.
2. Ввести неверный пароль → остаёмся на странице, в `logs/auth.log` появляется
   запись `FAILED LOGIN`.
3. Ввести `app_user` / `user_secret` → главная страница.
4. «Товары» → список с постраничной навигацией.
5. «Добавить» → заполнить форму → строка появляется в таблице.
6. «Изменить» → поменять цену → сохранить → значение обновилось.
7. Проверить фильтр `ids=1,2,3` — работает через `ANY(%s)`.
